# Poker Night App

A cute, mobile-first web app for running a home poker night: seat players at a table, track buy-ins, and at the end of the game calculate who pays whom, in whole shekels only.

The user plays on their phone at the table. Everything must be quick, simple, and work with one hand.

## Stack
- React + Vite + Tailwind
- Vitest for tests
- PWA (installable to home screen)
- State saved in localStorage so a refresh never loses the game

## Commands
- `npm install` – install dependencies
- `npm run dev` – run locally
- `npm test` – run the tests
- `npm run build` – production build
- `npx vite preview` – serve the build at `/Poker-Nights-/`, like GitHub Pages

## Branches (protect the live site)
- `main` is the live site: every push to it deploys to GitHub Pages. It must stay untouched.
- **Never push to `main` or merge into `main` unless the user explicitly says so in that moment.** No exceptions for "small" fixes.
- All new work happens on the `multiplayer` branch. Before committing, check `git branch --show-current`.
- The user tests changes locally with `npm run dev`; there is no preview deploy of the branch.
- Phone testing: Supabase Auth refuses to redirect to bare IPs, so the phone opens `http://<ip-with-dashes>.nip.io:5173` (e.g. `http://192-168-1-6.nip.io:5173`). `vite.config.js` allows only this machine's own nip.io names. Each such address must also be in Supabase → Authentication → URL Configuration → Redirect URLs.
- Tag `v1` marks the live version from before multiplayer work (a safe point to return to).

## Deployment
- GitHub Pages via `.github/workflows/deploy.yml`: every push to `main` runs the tests, builds, and deploys.
- The app lives at `/Poker-Nights-/` (Vite `base`). Keep manifest, icon and service-worker paths relative (or `%BASE_URL%` in `index.html`) so the PWA works under that path.
- Bump `CACHE` in `public/sw.js` when its caching logic changes.
- Commits use the GitHub noreply email, never the personal Gmail.

## Language & RTL (always)
- All UI text is in Hebrew: buttons, titles, warnings, empty states, copied WhatsApp text.
- `dir="rtl"` on the whole app. Layouts, icons and arrows must be mirrored correctly.
- Font: Rubik or Heebo (Google Fonts).
- Currency: number then ₪ (e.g. `150 ₪`).
- Player names may be typed in Hebrew and must display correctly.
- Code, comments, file names and commit messages stay in English.

## Features
1. **Start screen**: the app opens here, unless a table was open: a refresh or reopening the home-screen app returns to that table (`src/lib/screen.js`: `?table=<id>` in the URL + `poker-nights-screen` in localStorage). A game saved by the first version (v1: no `tableOpen` in the save) opens straight onto its table (`isLegacyGame`). The app reads the save **as stored** (`loadState({})`, never pre-merged with `initialState`) so `normalizeState` can tell a missing field from "false". It has two clearly separate sections:
   - "🌐 שולחן אונליין עם חברים" (requires Google sign-in): back to the latest open online table, or open a new one.
   - "📱 שולחן מקומי (בלי התחברות)": the phone-only table, exactly as before (stored in localStorage).
   Tapping the logo in a table returns here.
   - Online tables reuse the same table UI (`TableScreen`) as the local one; `src/lib/onlineTable.js` loads a table into the local state shape (`toView`) and writes changes to Supabase. Managers/co-managers get the edit controls; players see the table read-only (and in "כל אחד את שלו" mode can add buy-ins to their own seat). Header buttons: 💌 invite, 📜 log and ⚙️ table management (name, buy-in amounts, chip value, rounding, buy-in mode, co-managers, delete table).
2. **Table settings**: the table manager sets the initial buy-in and 2–4 quick re-buy amounts ("סכום אחר" is always available too). Stored per table in the game state and as the defaults for the next table (`poker-nights-settings` in localStorage). Adding a player preselects the initial buy-in; re-buy buttons use the chosen amounts.
   - **"שווי צ׳יפ"** (`settings.chipValue`, ₪ per chip: 1 / 0.5 / 0.25 / 0.1 or any 0.01–1000 via "אחר"; default 1; `ChipValuePicker`): chosen when opening a table, changeable in ⚙️ (local; online managers and co-managers, logged as `chip_value_changed`, locked once ended). **Buy-ins always stay in ₪**; only the chip counts typed at the end (and "יצא עם סכום" when leaving) are converted: `chipsToShekels` (1,500 × 0.5 = 750 ₪, rounded to whole ₪). A table whose chip isn't worth 1 ₪ opens the end-game screen in the chips mode. Results are stored in ₪ either way.
   - **Changing amounts mid-game** (an extreme night): ⚙️ on the local table (`LocalSettingsSheet`: rounding + chip value + amounts) and in the online ⚙️ table management (managers and co-managers; logged as `settings_changed` with the new amounts, live for everyone; locked once ended). Editor shared with the setup screen: `AmountsEditor` / `AmountsForm`. Changes only that table, not the saved defaults (local action `setAmounts`).
   - **"עיגול סכומים"** (`settings.rounding`: 1 / 5 / 10 / 50 ₪, default 10; `RoundingPicker`): chosen when opening a table (local and online) and again on the settlement screen ("מי מעביר למי"), since it depends on the night's amounts: the results update right away. Online only the manager changes it (there and in ⚙️; co-managers see it read-only), it's locked once the game ended, and logged. Local: the `setRounding` action changes only the open table, not the saved defaults. The settlement header doesn't show it (only the table name and date).
   - **Table name** (online only, optional, max 30 chars, e.g. "שישי אצל אסף"): set when opening, changed by the manager only in ⚙️. Shown in the center of the table above the pot, on the start screen, in the invite message, the log, the settlement/WhatsApp text, and later stats/history.
   - **Invite message**: "<manager name> הזמין אותך לשחק פוקר בשולחן '<table name>' 🃏 הצטרף כאן: <link>" (without the table part when there's no name). Link previews come from Open Graph tags in `index.html` (`public/og-image.jpg`, 1200×630, same for every table; absolute URLs on the live site, so previews only work once it's on `main`).
3. **Table view**: oval green felt table with a wood rim, up to 9 players. Before "המשחק התחיל": 9 fixed seats, each empty one with a "+" that seats a player there; "הוסף שחקן" fills the next free seat. After it starts: empty seats disappear, players spread evenly; latecomers are placed via "+" slots between players. Drag a player onto another seat to move/swap. Tap a player for re-buys, undo, remove, and the buy-in history (amount + time of each buy-in).
   - **Leaving mid-game** (after the start, managers/co-managers): "יצא מהמשחק 🚪" with the end-game labels and icons: "💀 הפסיד הכל" (0), "🤝 מאוזן" (what they put in), "🚪 יצא עם סכום" (any amount, more or less than they put in; the three are one row of tiles that opens right where "יצא מהמשחק" was tapped and scrolls into view; a player who already left has "שנה ✏️" to change the exit directly, without "חזר לשחק"; typed; when a chip isn't worth 1 ₪ the manager picks "צ׳יפים" (converted by the chip value) or "₪ שקלים"; stored in ₪ either way). **The player gives up their seat** (`seat` = null; the seated players after them move one seat back, so a full table gets room for a new player) and moves to the "יצאו מהמשחק" strip under the table (`LeftPlayers`: avatar with the exit icon instead of the initials, name, amount). They stay in the results and the settlement. The center of the table shows big "על השולחן" (everything bought in minus what players who left took: `onTableTotal`) and small "נכנס הערב" (all buy-ins: `potTotal`); "חזר לשחק" puts the amount back; the amount prefills the end-game screen. No buy-ins while out; "חזר לשחק" brings them back at the end of the table if a seat is free (else "אין כיסא פנוי") and clears the result. Constants: `EXITS`, `seatedPlayers` in `src/lib/game.js`; old local saves are migrated by `normalizeState`.
   - **"השאיר מזומן?"**: after a losing exit ("הפסיד הכל", or "יצא עם סכום" below what they put in) the sheet asks whether they left cash, as bills (see below), never more than the loss. It goes into the night's cash pot. Shown on their out card ("💵 השאיר 200 ₪ מזומן").
4. **List view** (not built yet): toggle from the table view. Each player's name, number of buy-ins and total in, with the pot at the bottom.
5. **End game**: enter each player's result as profit/loss (+/−, default) or final chips. One-tap "מאוזן" and "הפסיד הכל". Each card shows how much the player put in. If the totals don't balance, warn and allow continuing.
   - With a chip value other than 1 ₪ the chips mode takes **chip counts** and shows both numbers on the card ("1,500 צ׳יפים = 750 ₪"); the field keeps the typed count, the state holds the ₪. **One field per player with a 3-way selector above it: "רווח/הפסד / צ׳יפים / כסף" (in this order; default רווח/הפסד everywhere)** (`ResultField`, math in `src/lib/result.js`), on the end-game screen and in "יצא עם סכום", also when a chip is worth 1 ₪. Net takes + / − buttons (the iPhone number pad has no minus) and converts with the player's total buy-ins; a loss bigger than the buy-ins is refused. Under the field the other forms show small ("= יצא עם 100 ₪ · מינוס 100"). Everything is stored as the ₪ they leave with, so the totals check works with mixed styles. The old screen-wide "רווח / הפסד" / "צ׳יפים בסוף" switch is gone (endMode still decides the default style and how finals are kept).
   - **Bills**: each cash entry is one indivisible bill; a player can have several. Entering cash: quick buttons "💵 200 / 100 / 50 / 20" (each tap adds one bill, running total "50 + 50 = 100 ₪", tap a bill to remove it) or a typed amount added as one bill (`CashForm`, `BILLS`). Saved as one entry per bill (local `addCash` per bill; online one `cash_payments` row per bill). While the leave/cash flow is open the re-buy buttons are hidden, so the two can't be confused.
   - **"מזומן ששולם 💵"** (end-game screen): the cash entries (who paid, how much), each removable. Only players with a loss can be picked. Cash is recorded **only when settling** (leaving mid-game or at the end of the night), never as a running "paid cash" button during the game. State: `cash: [{ id, from, amount }]` (local reducer `addCash`/`removeCash`; online table `cash_payments`).
   - **The cash pot (rules, never break):** nobody "holds" the cash, and no holder is ever recorded or shown (no "אצל", no "נשאר אצל"). Cash is only a partial or full payment of a loser's debt: never more than their loss, so there is never change or money back.
   - **One source of truth per player (the last action wins):** for a player who left mid-game the result IS the exit (`player.out` locally, `out_kind`/`out_chips` online); for everyone else it's the end-game value (`finals` / `final_value`). Leaving clears an older end-game value (the exit wins); changing a leaver's value on the end-game screen updates the exit (`exitFor`: 0 = "הפסיד הכל", their buy-ins = "מאוזן", else "יצא עם סכום"), so the strip and "על השולחן" follow it; clearing it does nothing; "חזר לשחק" clears both. `netOf` and `finalChips` read exactly this. Old local saves with two values are merged (the end-game one wins). `ResultField` doesn't redraw while it's being typed in.
   - Online (`OnlineEndGame`): managers and co-managers enter results; typing is instant on the phone and saved ~0.6 s later, other managers' entries arrive live. Results are stored as what the player left with **in ₪** (`final_value`, chip counts already converted), so the +/− and chips modes are only input styles.
6. **Settlement**: list of `X → Y: amount ₪`, "שתף כתמונה 📸", and "new game" (back to the start screen).
   - **One list of rows**, cash included (no separate cash sections): each row is payer → receiver with the amount. A row paid **all in cash** has a 💵 (text-2xl on the screen, 22px in the image) before a green amount, and "← מזומן" in green under it. A **mixed** row keeps the usual yellow amount (only part of it is cash) and one line under it, "200 מזומן · 70 העברה" (cash green, transfer gray), that never wraps. No pills (`cashParts` in `src/lib/settlement.js`). Example: Nadav −250 who paid 200 → "נדב → עומר 250, 200 מזומן · 50 העברה": he transfers only 50. The results ("תוצאות הערב", `final_net`, stats) are the full nets, however they were paid.
   - **"מי לא כאן?"** (settlement screen, managers before closing; local always): a toggle per player. Players who left mid-game are "לא כאן" automatically (`isAbsent`: `player.absent` when marked by hand, else `out`); a hand mark overrides it either way (e.g. left but stayed to watch). **Cash is handed only to winners who are present**: an absent winner is paid by transfer, and the bills go whole to present winners (`settle(..., { absent })`). When no winner who is present can take a bill, someone else who **is** present takes it and passes it on by transfer, even if they lost (it's added to their own debt): the manager when present (online: the manager's seat), otherwise whoever keeps the settlement simplest. Only automatic, only when needed. Example: Ido paid 150 cash, the winner Tomer left, Fouad is here → "עידו → פואד 150 מזומן", "פואד → תומר 150" (combined with Fouad's own debt if he lost). Cash reaches an absent player only if nobody but the payer is present. Local: `setAbsent`; online: `table_players.absent` (null = automatic), logged as `presence_changed`. Example: Ido pays 150 cash, Tomer is owed 150 but left early → Ido's 150 goes to a present winner, Tomer gets a transfer.
   - **Share as image** (`src/lib/settlementImage.js`): the settlement card (title, table name · date, transfers with avatars, results, footer with the tagline) is drawn on a canvas at pixel ratio 3 (1170 px wide), after the Rubik font loads. Drawn directly rather than captured from the DOM, because DOM-to-image libraries are unreliable on iPhone Safari (fonts, emoji). It's prepared when the screen opens, so the tap calls `navigator.share({ files })` right away (Safari only opens the share sheet straight after a tap). Where sharing files isn't available (desktop, plain http like the nip.io address) the PNG is downloaded (`poker-nights-YYYY-MM-DD.png`). Same component for the local and the online table.
   - Online: after "מי מעביר למי", **only the manager** taps "סגור את השולחן 🔒" (twice). `public.end_game` stores every player's settled `final_net` and ends the table in one transaction; the database refuses unless every player has a result and they add up to 0. Then everyone at the table sees the settlement live (with confetti), the table is locked, and the manager can "פתח מחדש לתיקונים".
   - **Stored transfers + "שולם ✓"** (online): closing calls `public.end_game(table, nets, transfers)` with exactly the rows the manager saw (`settle` with cash, absent and manager). The database refuses transfers that don't match the results (`private.transfers_valid`, mirrored by `transferProblems` in `src/lib/settlement.js`, tested on thousands of random nights): each player receives − pays = `final_net`, the non-cash part goes only to winners and never above their win, no more cash than recorded. The closed table shows the stored rows (not recomputed), each with "פתוח" / "שולם ✓" and "N מתוך M שולמו" on top. The payer, the receiver, the manager and co-managers mark/undo (only `paid_at` is writable; the database stamps the time and `paid_by`), live, logged as `transfer_paid` / `transfer_unpaid`. Reopening deletes the stored transfers and marks. The old 2-argument `end_game` still works (no transfers).
   - **Phone for Bit** ("מספר טלפון (לביט)", optional, profile screen; Israeli mobile only, stored as 05XXXXXXXX, `src/lib/phone.js`): in its own table `profile_phones`, never in `profiles`. Visible only to its owner and to a user who has a stored transfer **to** them with a non-cash part, in a closed table (`private.pays_by_transfer_to`). Never in the share image, the log or the invite. On the payer's rows only: "העתק טלפון לביט 📋" copies the number, shows "המספר הועתק · 150 ₪ – הדבק בביט" (the transfer part) and opens Bit (`src/lib/bit.js`): iPhone → the universal link `https://www.bitpay.co.il/app/` (listed for the Bit app in Bank Hapoalim's apple-app-site-association), App Store if the page is still visible after 1.6 s; Android → an `intent:` URL for `com.bnhp.payments.paymentsapp` with Google Play as fallback; computers → copy only. Tested 2026-11-11 on the user's iPhone: Bit opens; every `/app/...` path (13 tried) opens only Bit's main screen, so there's no link to "transfer by phone number".
     - **Asking for the number when it's needed** (`PhonePrompt`): on a closed table, a winner who gets at least one transfer that isn't all cash and has no number sees "הוסף מספר טלפון כדי שיוכלו להעביר לך בביט" with a field and "שמור" on the settlement screen; "לא עכשיו" hides it for that table on that device (`poker-nights-phone-later:<table id>` in localStorage). Never asked at sign-up. A saved number isn't in the change log (private), so a payer whose receiver has no number yet reloads the table every 10 s while the screen is visible, and the Bit button appears by itself.
7. **Stats** ("📊 סטטיסטיקה והחבר׳ה שלי" on the start screen, signed-in only; `StatsScreen`). Only closed online games the viewer **played in** (had a seat) count; local tables never do; a reopened game drops out until it's closed again. Only the viewer sees their stats.
   - "📊 שלי": games, total net, average per game, best/worst night, an SVG chart (net per night as bars + running total line, oldest on the right for RTL, no chart library), fun facts ("הפסיד הכל" count = left with 0 chips, average buy-ins per night, current/best winning streak = nights in profit in a row, an even night breaks it), and the list of games (table name, date) that opens the table.
   - "👥 החבר׳ה שלי": everyone the viewer sat with, numbers only from those shared closed games; accounts by `user_id` with the profile name, guests grouped by name with an "אורח" mark; sort by total, games or average.
   - **Hiding / removing games** (e.g. test games): "⋯" next to a game (in "המשחקים שלי" and in "משחקים מוסתרים") opens two choices, both only about the viewer's own stats **and** their "החבר׳ה שלי":
     - "🙈 הסתר מהסטטיסטיקה שלי": can be undone ("🙈 משחקים מוסתרים (N)" → "הצג שוב").
     - "🗑️ מחק מהסטטיסטיקה שלי לצמיתות" (two taps): like hiding, but with no way back; it leaves the hidden list too.
     - Neither ever deletes the game or changes anything for other players. Deleting a whole table stays manager-only, in ⚙️ table management.
     - Stored per user in `hidden_games` (`permanent` = removed for good).
   - Logic: pure functions in `src/lib/stats.js` (tested); data from the views via `src/lib/statsData.js`.

## Settlement algorithm rules (do not break these)
- All amounts are whole shekels. Never show 2.5 or any fraction.
- Round each player's net to the table's **rounding unit** ("עיגול סכומים": 1 / 5 / 10 / 50 ₪, default 10; halves away from zero). If totals don't balance after rounding (or because of a counting mistake), absorb the difference into the biggest winner so everything balances exactly (the difference is a multiple of the unit, so the winner stays round). Every transfer is a multiple of the unit too: `settle(entries, { unit })` searches the plan in units (MIN_TRANSFER in units = ceil(20 / unit)) and scales back. Unit 1 = exactly the old behavior.
- **Cash bills** (`settle(entries, { unit, cash })`): each cash entry is one indivisible bill and goes **whole** to one winner who is still owed at least that much; different bills of the same player may go to different winners (two 50s to two people), one 200 never splits. The settlement tries the combinations (exact matches first, up to 400) and keeps the one with the fewest small transfers, then the **fewest rows** (a transfer between a payer and a receiver who already share cash adds no row: `bestPlan`'s free pairs), then the fewest transfers. Only a bill no winner is owed in full is split, into multiples of 50 (`splitUnfitBills`). Example: Ben −430 with one 200 bill → בן → פואד 270 (200 מזומן · 70 העברה), בן → קשקש 160, שקד → תומר 250, עידו → תומר 150. **Cash is only a (partial or full) payment of a loser's debt: never more than their loss, so there is never change or money back.** The forms block it (`cashRoom`: loss minus cash already recorded; a clear Hebrew message, save disabled; on the end-game screen only players with a loss can be picked, and "מי מעביר למי" is blocked if a changed result leaves cash above a loss); `settle` also caps it (`capCash`). The rest is settled by transfers under the rules below (in rounding units when the remaining amounts allow it). Returns `{ nets, cashPaid: [{ from, amount }] (one per payer), transfers: [{ from, to, amount, cash }] }` (`cash` 0..amount).
- **Absent winners** (`absent: [ids]`, `manager: seat id`): bills are placed only on present winners (splitting into 50s among them if needed); a bill none of them can take whole goes to a present "carrier" (the manager if present, else the search picks the simplest), whose balance grows by the bill so the transfers pass it on. Scores: least cash to absent players, then least carried cash, then the usual ones. Absent marks change nothing when there's no cash. This is the only case where someone receives cash they aren't owed, and it's shown just as a cash row plus their transfer (still no holder anywhere).
- Minimize the number of transfers.
- No transfer under 20 ₪. If matching leaves a small leftover, re-arrange which loser pays which winner until every transfer is ≥ 20 ₪. Only fall back to a small transfer if there is truly no other option.
- The algorithm lives in its own file (`src/lib/settlement.js`), separate from the UI, as a pure function.
- Run `npm test` after any change to the algorithm.

## Design
Cute and playful: soft shadows, rounded corners, chip and card icons, confetti on "End game". Dark mode by default. Large tap targets for phone use.
- **Bottom sheets** (`BottomSheet`): follow the visual viewport, so with the iPhone keyboard open the sheet sits right above it and never goes under the clock (safe area); the handle, title and ✕ stay on top and only the content scrolls; the page behind is locked. Name fields that aren't the phone owner's (guests, per-table names) and amount fields have contact autofill off. Taken colors in "הוסף שחקן" show the owner's initial and a small ✕. "הוסף שחקן" has two steps (`AddPlayerSheet`): 1. who: people who joined by invite and aren't seated as big names, then "או הוסף אורח" (name + color; nothing auto-focuses, so the keyboard never hides the list); 2. the first buy-in (amount buttons / "סכום אחר") with a back arrow.
- **Long names wrap, they aren't cut**: the first word on the first line, the rest on a second, slightly smaller line; single words stay on one line; a line is cut only if it still doesn't fit. Everywhere names appear: settlement rows, table seats, results, end-game cards, the player sheet, stats ("החבר'ה שלי") and the shared image. `PlayerName` (screens) and `splitName` (`src/lib/names.js`, also used by the image).
- Tagline: "הקלפים עליכם, החשבון עלינו" (start screen, `<title>`, meta/OG description, preview image).
- Logo: two cards, a red ♥ behind and a black ♠ in front, with a blue and a red chip (`CardsIcon` in `src/components/Icons.jsx`). The same art is the app icon: `public/icon.svg` (favicon), `icon-192.png`, `icon-512.png` (also maskable: content inside the safe zone), `apple-touch-icon.png` (180×180, full-bleed square; iOS rounds it). After changing icons, bump `CACHE` in `public/sw.js` (icons are cache-first).

## Roadmap (multiplayer branch)
Build in steps and stop for the user's confirmation after each step.
1. **Table settings, no backend** (done): start screen, table setup, settings used throughout the game.
2. **Supabase + Google login + shared tables + stats** (in progress), in steps:
   1. Connect: client in `src/lib/supabase.js`, env vars (done).
   2. Schema, grants, RLS as migrations + SQL tests that try to break the rules (done, 55 tests, Advisor clean).
   3. Google sign-in (done: desktop and the iPhone home-screen app).
   4. **Display names + colors**: pick a name (prefilled with the Google first name) and a color on first login; profile screen to change both; per-table nickname and color override set by the manager; guests get a manager-chosen color. Migration + RLS + tests.
   - **Decided before step 5:** co-managers + a per-table buy-in mode + a change log (see Roles). Built in step 5's first migration.
   5. Create a table online + manager controls: settings (incl. buy-in mode), seating flow, buy-ins/undo, co-managers, change log view, all in Supabase (done).
   6. **Invites** (done): "הזמן חברים" (Web Share, wa.me fallback, QR); opening the link → sign-in → auto-join → **the player picks their own free seat**. The manager can still move anyone and seat guests. Tested with Google Cloud test users until step 10.
      - RLS + tests: a member may insert only their own seat (`user_id = auth.uid()`), only once per table, only in a free seat, only before the game ends, with no nickname/color override and no results. ## Roles & security rules (never weaken)
- **Manager** (`poker_tables.manager_id`): everything in their table. Also plays. **Only the manager** appoints/removes co-managers, ends/closes (or reopens) the game, renames the table, changes the buy-in mode, changes the invite code and deletes the table.
- **Co-manager** (`table_members.is_co_manager`, set only by the manager): everything else the manager does in that table: buy-ins (add/change/delete), seating, per-table names/colors, marking players out/back, results, starting the game, amounts.
- **Ended table**: locked for everyone (no buy-ins, seats, exits or results) until the manager reopens it; only its name may still change. `final_net` always adds up to 0 per table.
- **Buy-in mode** (table setting, chosen when opening, changeable by the manager): `managers` "רק מנהלים" (default): only manager + co-managers write. `self_add` "כל אחד את שלו": additionally each player may **add** buy-ins for **their own seat only**; no changes, no deletes, nothing for others. Corrections stay with the managers.
- **Change log** (`table_log`): every add/change/remove of buy-ins, seats, names/colors, exits/returns, cash payments, results, members, co-managers, game start/end, table name and settings, with who and when. Visible to everyone at the table, written only by triggers, so it can't be forged, edited or deleted.
- **Member/player**: otherwise passive. Reads the live table (seats, buy-ins, pot), the log and their own stats. Other writes: own buy-ins in `self_add` mode, and (from step 6) taking their own free seat once after joining.
- **Stranger**: sees nothing. **anon**: has no grants at all.
- **Stats** come only from rows the viewer can read, i.e. tables they were part of. Never compute stats with elevated privileges: stats views are always `security_invoker = true`, filter on `auth.uid()`, count only `status = 'ended'` tables where the viewer has a seat, and are granted `select` to `authenticated` only.
- Policy helpers are `SECURITY DEFINER` with `search_path = ''` in the `private` schema (not exposed by the API). Never put SECURITY DEFINER functions in `public`.
- Every new table: enable RLS, add policies, add explicit grants (never to `anon` unless truly public), index foreign keys, and extend `supabase/tests/rls_test.sql`.
- `supabase/tests/rls_test.sql` must pass (400+ cases) after every schema change. It runs as one DO block and rolls itself back by raising at the end; the error text is the report.

Design rules so phase 1 code carries over:
- The game state is one **table**: `settings`, `players`, `started`, `finals`, `endMode`. Later this maps onto Supabase rows: `tables` (settings, status, manager), `table_players` (seat, optional user id, guest name), `buy_ins` (amount, time, status: pending/approved), `results`.
- Keep all game rules in pure functions in `src/lib/` (reducer, settlement). The UI dispatches actions; a backend will later persist the same actions, not replace the logic.
- Buy-ins are already stored with their time; add a status (approved/pending) when shared tables arrive.
- Until phase 2 is requested: no backend, no accounts, no new libraries.
